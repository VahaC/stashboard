## Highlights

A VM's **Config** tab used to be **read-only** — every guest-config change beyond
create / clone / restore meant opening the Proxmox web UI. Now it's **writable**, reusing
the exact same edit surface the LXC modal has had since 6.5 / 6.9 (inline editing, a
single **Save** that commits only the keys you changed, and client-side guards that
mirror the server). The day-to-day "tweak a guest" loop now works for VMs just as it does
for containers.

Open a VM, go to **Config**, hit **Edit**, change what you need, then **Review changes →
Apply**. There's nothing to turn on — config editing isn't gated (it needs the API
token's `VM.Config.*` rights, which Proxmox enforces).

## What you can change

- **Scalars** — name, cores (per socket) and sockets, memory, an optional balloon
  minimum, start-at-boot, OS type, the **QEMU guest-agent** toggle, the boot order, and
  the description / tags. Only the fields you actually change are sent.
- **Network interfaces** — add, edit or remove `net<n>` NICs with a structured row
  editor: device **model** (virtio / e1000 / …), bridge, VLAN tag, MAC, rate, MTU,
  queues, firewall and link-down. Options Stashboard doesn't model are preserved, and any
  row can be edited as raw.
- **Install media** — swap the `ide2` CD-ROM to another ISO, or eject it.
- **Disks** — toggle the safe flags (discard / SSD emulation / cache) as part of Save,
  **grow** a disk (grow-only — shrinking is unsafe), and **move** a disk to another
  storage (copied in the background and task-polled, like a clone).

## Safety & audit

Proxmox stays authoritative: cores / sockets / memory ranges, the balloon ceiling, MACs,
VLAN tags and NIC models are checked before the request leaves Stashboard, and any host
rejection is surfaced **verbatim**. A running VM is flagged after Save when a change (CPU
/ memory / NIC) only takes effect on the next **stop + start**.

Every applied change is recorded on the Audit page's new **Guest config** tab — who,
when, host, node, vmid, kind, what changed, and the result. The LXC config editor now
writes to the same trail, so container and VM edits share one history.

### Not included yet

Changing BIOS / machine on an existing VM, PCI / USB passthrough, cloud-init drives,
CPU type / NUMA / topology beyond cores and sockets, and adding or removing a whole disk
are out of scope for now — this phase makes the everyday editable surface writable.
