## Highlights

The browser **console** that shipped for LXC containers in 6.6 now works for
**QEMU/KVM virtual machines** too — closing the last container-only gap. A VM's
**Console** tab now shows the VM's **screen**, live, right inside Stashboard: the same
VNC display the Proxmox web UI opens, rendered with **noVNC**, with full keyboard and
mouse control and a canvas that fits the panel. You can finally install a guest OS from
the ISO you booted, poke at a VM with no network, or fix a broken boot — without leaving
the dashboard.

A VM has no `pct exec` and no guaranteed SSH, so this isn't the SSH shell the LXC
console uses — it's the VM's built-in **VNC** screen. Stashboard relays it
**server-side**: it opens the Proxmox VNC websocket from the backend and streams it to
your browser byte-for-byte, so the **Proxmox API token never reaches the browser**.

## Turning it on (off by default)

This reuses the **same** switch as the LXC console — there is nothing new to enable if
you already turned the console on for containers. (That switch is now named **Guest
console** — it was called *LXC console* before, since it now governs both guest kinds.)
It takes **two** switches plus a running VM, and until both are on the live screen stays
hidden (and the server refuses the request regardless):

1. **Enable it server-wide.** Go to **Settings → Guest console** and tick
   **Enable the guest console server-wide**, then **Save**. (This one switch governs both
   the LXC shell console and the VM VNC console.)
2. **Opt the host in.** On the **Proxmox** page open the host's menu (**⋮ → Edit**),
   tick **Allow guest console**, and save.
3. **Start the VM.** The console attaches to a live VNC display, so the VM must be
   **running**.

Then open the VM (click its card on the **Proxmox** page) and pick the **Console** tab.
Click **Connect** and the VM's screen appears. Unlike the LXC console, a VM does **not**
need SSH configured on the host — the VNC console uses the API token.

## Safety & audit

The same guardrails as the LXC console apply. Every session is **audited** on the Audit
page's **Guest console** tab — who connected, when, to which host / node / VM, how long, how
much data flowed, and why it ended — alongside the LXC shell sessions. The per-user and
per-host **concurrency caps** and the **idle timeout** are shared with the LXC console
(tunable via `STASHBOARD_Stashboard__ProxmoxConsole__*`). The WebSocket is authorised by
a single-use, short-lived ticket — never a token on the query string — and the Proxmox
API token stays on the server: the browser only ever receives the one-time VNC password
the screen itself challenges for.

### Heads up

If a host's Proxmox version refuses token-authenticated VNC relay, or the VM has no VGA
console, the Console tab shows a clear **"console unavailable on this host"** message
instead of a blank or hung canvas — it never leaves a broken connection open.

### Not included yet

SPICE (which needs a native viewer like `virt-viewer`), clipboard / audio / USB
redirection, and the serial console for VMs without a VGA device are out of scope.
