## Highlights

This release brings full **clone** and **snapshot** management for Proxmox LXC
containers, plus an in-app **What's new** panel so you can see exactly what each
release changed — right from the sidebar.

## Clone & snapshot LXC

### Clone an LXC

A guest's **Lifecycle** action row now has a **Clone** button. It opens a dialog
where you choose:

- a new **VMID** (pre-filled from the cluster's next free id),
- a **hostname**,
- an optional **target storage**,
- **full** vs **linked** clone, and
- when the source has snapshots — an optional **source snapshot** to clone from.

The clone runs as a real Proxmox task that Stashboard polls to completion, so you
get a genuine success/failure result. On success the host is re-scanned and the
cloned container shows up immediately.

### Snapshots tab

The LXC modal gains a **Snapshots** tab where you can:

- **Take** a snapshot (name + optional description),
- **Roll back** to a snapshot (double-confirmed — it discards newer state), and
- **Delete** a snapshot.

Each action is a polled Proxmox task, so the UI reflects the real outcome.

### Safety & audit

Clone and all snapshot writes are **double-gated**, exactly like create/destroy:
a master switch in **Settings → Clone/snapshot LXC** plus a per-host opt-in, both
**off by default**. Every clone, snapshot, rollback and delete that reaches the
host is recorded on a new per-guest **Audit** tab (who, when, host, node, vmid,
action, result).

### Not included yet

Cross-node / cross-cluster clone migration, scheduled snapshots, and snapshot
trees beyond a flat list are deferred to a later release.

## What's new panel

A new **What's new** entry sits in the sidebar, just under **Setup guides**. It
opens a panel that lists every Stashboard release with detailed notes — pick a
version on the left, read what changed on the right.

- **Opens automatically once after an upgrade.** Stashboard remembers the last
  version you saw, so the panel pops up a single time when you move to a newer
  build (a fresh install is never greeted with it). A small dot on the link marks
  notes you haven't read yet.
- **Always available.** Click **What's new** any time to re-read the history.
- **Driven by per-release files.** Each release's notes live in their own
  markdown file, rendered with full formatting (headings, lists, links, code).
