## Highlights

Stashboard already knows which of your containers, guests and services are up, which
Docker images have an update waiting, and which sites are responding. **9.0** hands all
of that to **Home Assistant** — automatically.

Turn on the new **MQTT / Home Assistant** integration, point it at your existing MQTT
broker (e.g. Mosquitto), and Home Assistant **auto-discovers** the matching entities with
**zero YAML and no HACS add-on**. Three kinds of sensor show up:

- **Running state** — a sensor per Docker container *and* per Proxmox LXC / VM guest
  (on = running).
- **Update available** — a sensor per Docker container (on = a newer image is waiting).
- **Service health** — a sensor per monitored service (on = online).

Now you can build HA dashboards over your whole estate and wire up automations like
*"notify me when a container goes down"* or *"alert me when a Docker update appears"* —
using the notification channels you already run in Home Assistant, without Stashboard
re-implementing them.

This release is **publish-only**: Home Assistant *observes* your estate, it can't control
it. Starting or stopping a container from HA is deliberately left for a later phase.

## How it looks in Home Assistant

Every entity is prefixed with your **entity prefix** (default `stashboard`), so they're
trivial to spot, group and filter — e.g. `binary_sensor.stashboard_jellyfin_running`.
Each real object — a Docker container, a Proxmox guest, a service — is its **own** Home
Assistant device under a single **Stashboard** hub, so you get a tidy device tree instead
of one giant device. (A container and an LXC that merely share a name stay separate
devices.) A service's health sensor joins the device of the container or guest you
**linked** it to, so its running + update + health sit together.

All entities share an **availability** topic, so they flip to *unavailable* the moment
Stashboard stops or loses the broker connection — you see "unavailable", never a stale
last value. When a container / guest / service goes away, its entity is removed from Home
Assistant automatically rather than lingering as an orphan.

## Turning it on (off by default)

1. Go to **Settings → Home Assistant**.
2. Tick **Enable the MQTT / Home Assistant integration**.
3. Fill in your **broker host** and **port** (and TLS / username / password if your broker
   needs them). Stashboard uses your **existing** broker — it doesn't run one.
4. *(Optional)* Adjust the **discovery prefix** (must match Home Assistant's MQTT
   discovery prefix, default `homeassistant`) and the **entity prefix** (default
   `stashboard`).
5. Click **Save**. Use **Test connection** to confirm the broker is reachable.

The entities appear in Home Assistant within a check cycle. The broker password is
**encrypted at rest** and never shown again, and the whole config travels with your
**backup / restore**.

### Heads up

- Changing the **entity prefix** re-publishes everything under the new ids and clears the
  old ones — Home Assistant ends up with one clean set of entities, not duplicates.
- This integration publishes **state, update and health** signals only. Raw CPU / RAM /
  disk metrics are deliberately out of scope — Home Assistant users who want host graphs
  already have purpose-built tools for that.
