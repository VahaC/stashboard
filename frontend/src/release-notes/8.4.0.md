## Highlights

The **create-from-scratch** workflow that shipped for LXC containers in 6.13.1 now
works for **QEMU/KVM virtual machines** too. Define a brand-new VM — its hardware and
an install ISO — and Stashboard provisions it on the host and boots it into the
installer, all from the Proxmox page without opening the Proxmox web UI. It's the exact
same surface as the container create, not a parallel one.

With this, **every** "make a guest" path in Stashboard — **create, clone, restore** —
is now mirrored for VMs as well as containers.

## Turning it on (off by default)

This reuses the **same** create gates as 6.13.1 — there is nothing new to enable if you
already turned create on for containers. It takes **two** switches, and until both are
on the **New VM** button stays hidden (and the server refuses the request regardless):

1. **Enable it server-wide.** Go to **Settings → Create guest** and tick
   **Enable create guest server-wide**, then **Save**. (This is the page that used to
   be called *Create LXC* — it now governs both containers and VMs.)
2. **Opt the host in.** On the **Proxmox** page open the host's menu (**⋮ → Edit**),
   tick **Allow create**, and save.

Once both are on, open the host's actions menu (the **⋮** button in its header) and
pick **New VM** (next to **New LXC**).

## Create a VM

The **New VM** dialog reuses the container-create surface, with VM hardware fields:

- **Identity** — a VMID (defaulted to the cluster's next free id), an optional name,
  tags and a description.
- **Installation media** — a dropdown of the node's `iso` images (or paste a volid by
  hand, or pick **No install media**). The ISO is attached as a CD-ROM and the VM boots
  into it — installing the OS is then up to you, via the host's **Console**.
- **System disk** — a primary SCSI disk on a chosen images-capable storage, sized in
  GiB. Extra disks can be added later from the VM's Config tab.
- **Resources** — cores (per socket), sockets, and memory.
- **Network (net0)** — a virtio NIC on a bridge, with optional VLAN tag / MAC /
  firewall.
- **System** — the guest **OS type**, **BIOS** (SeaBIOS or OVMF/UEFI) and **machine**
  type (q35 or i440fx). Pick OVMF and Stashboard provisions its EFI vars disk for you.

Create calls `POST …/qemu` with the assembled hardware (`scsi0` / `net0` / `ide2` /
`bios` / `machine` / boot order) and polls the task to real success or failure — not a
fire-and-forget "request accepted".

## Safety & audit

The same guardrails as container create apply: the VMID range, network, firmware / OS
type and sizes are checked before the request leaves Stashboard, and a VMID already in
use is rejected. A host rejection (a storage that can't hold the disk, a missing ISO) is
surfaced verbatim. Every attempt that reaches the host is recorded on the Audit page's
**Create** tab (who, when, host, node, vmid, name, source, result) — the same trail as
containers, now covering both kinds. A successful create re-scans the host so the VM
card appears right away, ready to boot into its installer.

### Not included yet

PCI / USB passthrough, multiple disks or NICs at create time, cloud-init drives, and
importing an existing disk image are out of scope — create the VM, then refine it from
its Config tab. Installing the guest OS itself is your job: this provisions the machine
and boots it to the installer.
