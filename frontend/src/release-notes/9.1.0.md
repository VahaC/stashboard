## Highlights

9.0 handed Home Assistant your **state** — what's running, what has an update, what's
online. **9.1** hands it the **conclusions Stashboard draws** from that state, so you can
automate over Stashboard's own verdicts instead of re-deriving them in Home Assistant.

With the MQTT integration on, four new kinds of entity auto-discover alongside the 9.0
ones — same broker, same prefixes, same tidy device tree, no extra setup:

- **Pending-update counts** — a *number* sensor (not just on/off) for how many updates are
  waiting, per **Docker host**, per **Proxmox node** (apt), and per **monitored LXC**.
- **Node alerts** — a **problem** sensor per Proxmox **PVE / PBS node** that turns *on*
  whenever Stashboard's own node alerting (the same logic behind the Alerts tab) raises a
  **warn or crit**, and back *off* when it clears.
- **Backup freshness** — a **timestamp** sensor per guest showing when its most recent
  vzdump backup was taken, so Home Assistant renders *"3 days ago"* and you can alert on a
  stale backup.
- **Estate roll-ups** — a single **Stashboard** device with at-a-glance totals: containers
  running / total, guests running / total, services online / total, hosts reachable, and
  total updates pending across everything.

And you can now **rebrand how the integration looks in Home Assistant** — give the
**hub device** and the **manufacturer** your own names (both default to `Stashboard`), so
the whole tree can read e.g. *Homelab* instead.

Now you can wire automations like *"notify me when any node raises a crit alert"*, *"warn
me if a VM hasn't been backed up in 7 days"*, or *"remind me on Sunday if any updates are
pending"* — one trigger, off Stashboard's own numbers.

This stays **publish-only**: Home Assistant observes, it doesn't control anything.

## The details

### Update counts
The 9.0 "update available" sensor told you *whether* an update was waiting. 9.1 adds the
**how many**: a numeric sensor that sits on the same device as the container it belongs to
(for Docker, the count rolls up onto a per-**host** sensor), and one per Proxmox node and
monitored LXC. Great for a single "12 updates pending across the homelab" badge.

### Node alerts, surfaced to HA
The per-node **problem** sensor mirrors Stashboard's node alerting exactly. Expand it in
Home Assistant and you'll find attributes for the **worst active severity** and a
**breakdown per category** — CPU, memory, storage, thermal, SMART and network — plus a
short detail for the breaching metric. So HA can tell you *"node raised a crit"* and *which
category* without you opening Stashboard.

### Backup freshness
Each guest gets a `timestamp` sensor set to the creation time of its newest vzdump archive.
Home Assistant shows it as a relative age and lets you alert when it gets too old. The
backup list is read straight from your Proxmox storages (and cached briefly so it doesn't
hammer the API every cycle).

### Estate roll-ups
The **Stashboard** hub device — the one 9.0 already created as the root of your device tree
— now carries summary sensors for the whole estate, so you don't have to template them
together yourself in Home Assistant.

### Make it yours
Two new fields on **Settings → Home Assistant** let you rebrand the integration: the
**hub device name** — the single device everything nests under in Home Assistant's device
list (default `Stashboard`, rename it to e.g. `Homelab`) — and the **manufacturer** stamped
on every Stashboard device (the *Manufacturer* column in HA). Both default to `Stashboard`
and travel with backup/restore.

## Turning it on (off by default)

These sensors ride the **same** integration switch as 9.0 — there's no separate toggle. If
you already enabled it in 9.0, they appear automatically within a check cycle.

1. Go to **Settings → Home Assistant**.
2. Tick **Enable the MQTT / Home Assistant integration**.
3. Fill in your **broker host** and **port** (and TLS / username / password if needed),
   then **Save**. Use **Test connection** to confirm the broker is reachable.

A couple of the new signals have their own prerequisites:

- **Node-alert sensors** only appear for a node once you've enabled **node alerting** for
  that Proxmox host (the same setting that drives the Alerts tab — host menu → node
  health / alert settings). No alerting configured ⇒ no problem sensor for that node.
- **Backup-age sensors** need Stashboard to reach the Proxmox host's storages, so they show
  up only for PVE connections that are reachable.

### Heads up

- Everything is still **retained** and shares the 9.0 **availability** topic, so the new
  sensors also flip to *unavailable* when Stashboard stops, and their topics are cleared
  when the host / guest / service goes away.
- This is still **state + derived signals** only — raw CPU / RAM / disk telemetry remains
  deliberately out of scope.
