## Highlights

The **clone** and **snapshot** workflows that shipped for LXC containers in 8.0.0 now
work for **QEMU/KVM virtual machines** too. Stamp out a copy of a known-good VM, or
take a snapshot before a risky change and roll back if it goes wrong — all from the
Stashboard VM modal, without dropping to the Proxmox web UI. It's the exact same
surface as the container version, not a parallel one.

## Turning it on (off by default)

This reuses the **same** clone/snapshot gates as 8.0.0 — there is nothing new to
enable if you already turned it on for containers. It takes **two** switches, and
until both are on the **Clone** button and the **Snapshots** / **Audit** tabs stay
hidden (and the server refuses the request regardless):

1. **Enable it server-wide.** Go to **Settings → Clone/snapshot** and tick
   **Enable clone/snapshot server-wide**, then **Save**.
2. **Opt the host in.** On the **Proxmox** page open the host's menu (**⋮ → Edit**),
   tick **Allow clone/snapshot**, and save.

Once both are on, open a **VM** card to find the **Clone** button on the Overview
tab's Lifecycle row and the new **Snapshots** and **Audit** tabs.

## Clone a VM

The **Clone** button opens the same dialog as the container clone, with VM wording:

- a new **VMID** (pre-filled from the cluster's next free id) and a **Name**,
- **full vs linked** clone (a linked VM clone needs the source to be a template),
- on a full clone, an optional **target storage** and an optional **disk format**
  (`qcow2` / `raw` / `vmdk`; blank keeps the source's format), and
- when the source has snapshots, an optional **source snapshot** to clone from.

As with containers, Proxmox won't clone a **running** VM from its live state — pick a
source snapshot or stop the VM first; the dialog guides you before the host rejects
it.

## Snapshot a VM — with optional RAM state

The **Snapshots** tab lists, takes, rolls back and deletes a VM's snapshots, exactly
like the container tab. The one VM-only addition: when the VM is **running**, a
**Include running memory state (RAM)** toggle captures the live memory in the
snapshot, so a rollback resumes exactly where it left off (it's larger and slower).
Rollback and delete still require an explicit **double-confirm**, because a rollback
discards any state newer than the snapshot.

## Safety & audit

Every clone / snapshot / rollback / delete that reaches the host is recorded on the
VM modal's **Audit** tab (who, when, host, node, vmid, action, target, result) — the
same audit trail as containers. A host rejection is surfaced verbatim, and a
successful clone re-scans the host so the new VM card appears right away.

### Not included yet

Cross-node clone migration, scheduled snapshots, and nested snapshot trees are
deferred — same exclusions as the 8.0.0 container release.
